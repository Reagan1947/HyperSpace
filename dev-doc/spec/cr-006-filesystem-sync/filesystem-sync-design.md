# 文件树与磁盘双向同步设计

## 目标

文件树是项目目录的视图，不再存在独立的 HyperSpace 页面实体：

- 文件和目录的名称、层级、存在性以磁盘为准。
- 颜色标记、标签、收藏等应用元数据保存在 `.hyperspace/nodes`。
- UI 发起的重命名、移动和删除必须先成功修改磁盘，再更新内存状态。
- 磁盘侧新增、删除、重命名或移动通过目录监听实时反映到文件树。

## 身份与合并

`localPath` 只表示当前位置，不能作为长期身份。扫描节点同时保存：

- `id`：HyperSpace 稳定节点 ID，用于标签、标记、打开页签等引用。
- `localPath`：项目根目录下的相对路径。
- `fileIdentity`：平台文件系统 identity；Unix 使用 device/inode。

扫描时按以下优先级合并：

1. 相同 `localPath`：沿用已有 `id` 和应用元数据。
2. 路径不同但 `fileIdentity` 相同：视为磁盘侧重命名或移动，沿用已有 `id` 和元数据，并采用新的路径、标题和父节点。
3. 均未命中：创建新节点 ID。
4. 元数据中存在但磁盘扫描不存在：从文件树移除，并在保存时清理失效 sidecar。

文件内容采用原子写入时 inode 可能变化，因此保存 Markdown 后必须重新读取并持久化最新 `fileIdentity`。

## UI 发起的操作

### 重命名

1. 前端提交旧 `localPath` 和新文件名。
2. 后端验证路径必须位于项目内、文件名不含路径分隔符、目标不存在。文件夹允许命名为 `.assets`，其它以点开头的名称仍拒绝。
3. 后端调用文件系统 rename。
4. 成功后前端保留节点 `id`，更新标题和 `localPath`；目录重命名同时重写所有后代路径。
5. 失败时保持 UI 原状并显示错误。

### 移动

1. 前端提交源 `localPath` 和目标目录的相对路径（空字符串表示项目根目录）。
2. 后端验证源和目标都位于项目内，并拒绝把目录移动到自身或子孙目录中。
3. 同目录内排序不改动磁盘；跨目录调用文件系统 rename。
4. 目标已存在同名项时使用与新建相同的去重规则，不覆盖。
5. 成功后前端保留节点 `id`，更新 `parentId`、`localPath` 和标题；目录移动同时重写所有后代路径。
6. 失败时保持 UI 原状并显示错误。

### 删除

1. 前端仅提交用户选择的根节点路径。
2. 后端再次验证每个路径位于项目内。
3. 文件使用 remove-file，目录使用递归 remove-dir。
4. 全部成功后前端移除节点、后代、页签和 Markdown 缓存。
5. 失败时不提前修改 UI。

## 磁盘侧操作

打开项目后持续监听项目目录。Watcher 事件只作为“可能变化”的提示，最终状态仍通过重新扫描确认：

- 忽略 `.hyperspace`、隐藏文件、应用内部目录，以及原子写入产生的 `*.tmp`。`.assets` 附件目录是例外，会进入文件树并接收目录监听。
- 应用自己的新建、重命名、移动、删除和保存会短暂抑制回环；抑制结束后如果期间还有外部事件，会再扫描一次。
- 外部新增和删除由扫描结果决定；外部重命名或移动通过 `fileIdentity` 与原节点回连，所以标记、标签和稳定引用不会因路径变化而丢失。
- 仅当某篇 Markdown 相对上次同步的磁盘内容确有未保存修改时，扫描才保留编辑器缓冲。未修改的打开文件以磁盘为准，避免外部编辑被自动保存覆盖。
- 保存时若磁盘内容已相对 HyperSpace 上次写入发生变化，而本次提交的仍是上次写入的正文，则不得覆盖磁盘。

打开项目时始终重新扫描目录，而不是直接信任缓存节点。

当前非 Unix 平台没有可靠的 `fileIdentity` 实现，仍可按路径保留元数据，但外部重命名可能被识别为删除后新建。后续 Windows 实现应使用 volume serial number 与 file index，不能退回路径哈希作为稳定身份。

## 安全约束

- 后端不接受绝对路径、`..`、`.` 或多段新文件名。
- 不允许覆盖已存在的目标。
- 隐藏文件和应用内部目录仍由扫描忽略规则控制；允许将文件夹命名为 `.assets`，并在文件树中展示该目录及其内容。
- 磁盘操作失败时不得只修改前端状态。
