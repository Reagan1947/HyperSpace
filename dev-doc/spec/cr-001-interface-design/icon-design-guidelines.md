# HyperSpace 组态工具图标设计准则

## 1. 文档说明

本文档用于指导 HyperSpace 中工具栏、编辑器、画布组件与状态反馈图标的设计、补充、实现和验收。

- 参考图标集：[iconfont「组态工具」](https://www.iconfont.cn/collections/detail?spm=a313x.search_index.0.da5a778a4.de003a81lj7LVD&cid=20269)
- 参考范围：该合集公开展示的 71 个图标
- 分析日期：2026-08-15
- 适用场景：工具栏、活动轨、菜单、树节点、画布控件、状态提示
- 不适用场景：品牌 Logo、彩色插画、文件缩略图、大尺寸装饰图形

本文不是对参考图标的逐个复制，而是从其视觉语言中提炼可持续扩展的规则。文中“观察结论”描述原合集的客观特征；“项目规则”是面向 HyperSpace 的规范化落地要求。

## 2. 风格定位

### 2.1 核心气质

图标整体采用“轻量工业工具”风格：

1. **理性**：以基础几何形、平行线、对称结构和明确方向表达操作语义。
2. **克制**：主色为中性灰，不依赖高饱和色或强阴影吸引注意。
3. **轻薄**：轮廓细、留白多，适合高密度编辑器界面。
4. **可操作**：优先表达动作、对象与状态，不追求装饰性细节。
5. **微层次**：部分图标以浅灰填充区分前后层、选中对象或实体表面。

一句话定义：**以中灰轮廓为骨架、浅灰面为辅助，在统一方形画布内表达清晰的编辑器操作语义。**

### 2.2 观察结论

对参考合集的 SVG 与展示页抽样结果如下：

| 项目 | 观察结果 |
| --- | --- |
| 图标数量 | 71 |
| 源画布 | 全部使用 `viewBox="0 0 1024 1024"` |
| 页面预览尺寸 | 36 × 36 px |
| 主轮廓色 | `#7D7D7D`，71/71 个图标使用 |
| 辅助填充色 | `#CBCBCB`，36/71 个图标使用 |
| 反白色 | `#FFFFFF`，仅 2/71 个图标用于局部反白 |
| SVG 绘制方式 | 使用闭合 `path` 填充成形，未使用 `stroke` 属性 |
| 构图特征 | 单色轮廓或双色“轮廓 + 浅填充”，无渐变、阴影和纹理 |

## 3. 视觉构成规则

### 3.1 画布与安全区

项目统一以 1024 × 1024 为源画布：

```text
┌──────────────────────── 1024 ────────────────────────┐
│                    64–96 安全边距                    │
│      ┌────────────────────────────────────────┐      │
│      │             图标有效绘制区             │      │
│      │              832–896 px                │      │
│      └────────────────────────────────────────┘      │
│                    64–96 安全边距                    │
└──────────────────────────────────────────────────────┘
```

项目规则：

- 默认安全边距为 64 px；视觉重量较大的封闭图形可增加到 80–96 px。
- 图形优先在画布中几何居中；箭头、播放、发布等视觉重心偏移的图形需要做光学校正。
- 同组图标的外接框不必机械等大，但视觉面积应相近。
- 不允许关键细节进入 48 px 边缘区，避免小尺寸渲染时贴边。

### 3.2 轮廓粗细

参考图标虽然通过填充路径实现，但视觉上表现为统一的细轮廓。

项目规则：

- 1024 画布上的目标轮廓厚度为 **46–52 单位**，标准值取 **48**。
- 同一图标内只使用一种主轮廓厚度；不得用粗细变化制造装饰效果。
- 次要分隔线与主轮廓同粗，必要时最多缩减至主轮廓的 80%。
- 线段端部优先使用圆头或视觉等效的圆角闭合路径。
- 小尺寸下优先保证轮廓连续，不保留无法清晰显示的微小缝隙。

建议的屏幕等效值：

| 使用尺寸 | 建议视觉线宽 |
| ---: | ---: |
| 16 px | 1 px |
| 20 px | 1 px |
| 24 px | 1.25 px |
| 28 px | 1.5 px |
| 32 px | 1.5 px |
| 36 px | 1.5–1.75 px |

### 3.3 圆角与端点

- 外轮廓圆角以“轻微柔化”为准，不使用明显胶囊化造型。
- 标准线端圆角半径约为轮廓厚度的 50%。
- 面板、文件、文件夹、按钮等实体对象使用小圆角；圆角不应成为视觉主角。
- 箭头尖端、折线与管道转角保持明确，不因圆角而削弱方向性。
- 同类容器图标必须统一圆角半径，例如所有“页面/弹窗/文件夹”图标共用一档圆角。

### 3.4 色彩

#### 基础色板

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--icon-primary` | `#7D7D7D` | 外轮廓、关键符号、主要结构 |
| `--icon-secondary` | `#CBCBCB` | 实体表面、背层、选中块、弱化区域 |
| `--icon-knockout` | `#FFFFFF` | 封闭填充上的局部反白，仅在必要时使用 |
| `--icon-bg` | `transparent` | 默认背景 |

使用规则：

- 主轮廓色必须承担语义识别，移除辅助填充后图标仍应可辨认。
- 辅助填充只用于区分层级、实体与空腔，面积通常不超过图标有效面积的 35%。
- 单个图标默认最多使用主色与辅助色两档灰。
- 禁止在基础图标资源中写入品牌紫、成功绿、警告黄或错误红；状态色由组件层统一覆盖。
- 禁止使用渐变、透明叠色、投影、描边发光和材质纹理。

#### HyperSpace 状态映射

以下为项目层的交互色规则，不属于参考合集的原始色板：

| 状态 | 处理方式 |
| --- | --- |
| 默认 | 使用 `--icon-primary` / `--icon-secondary` |
| Hover | 主轮廓切换为当前文本强色，不改变内部结构 |
| Active / Selected | 主轮廓整体切换为品牌紫，辅助填充使用品牌紫的浅色阶 |
| Disabled | 整体降低不透明度，不单独修改某一条路径 |
| Success / Warning / Error | 仅在明确状态语义下整体着色，不与品牌紫混用 |

### 3.5 层次与填充

参考合集常用“深色轮廓 + 浅灰实体面”表达层次，例如置顶/置底、组合、文件夹、图片、表格和控件。

项目规则：

1. 最前层对象使用主轮廓色强调边界。
2. 背层、实体内部或非主要对象使用辅助填充色。
3. 重叠对象之间至少保留一个主轮廓厚度的可见分界。
4. 浅灰填充必须被主轮廓约束，避免成为无边界色块。
5. 除反白孔洞外，不用白色模拟擦除；应优先使用复合路径或透明负形。

### 3.6 几何语言

- 优先使用矩形、圆、平行线、45° 斜线、直角折线和规则圆弧。
- 操作类图标以“对象 + 动作标记”组合，例如文件 + 加号、文件夹 + 下载箭头。
- 对齐与分布类图标必须使用统一基准线、等距关系和对称轴。
- 方向类图标应保持箭头尺寸一致，箭头主体不超过有效绘制区的 70%。
- 重复、撤销、重做等圆弧图标的开口与箭头方向必须明显，避免仅靠名称区分。
- 关闭、成功、失败等状态符号优先放入圆形或明确容器中，保持成组一致。

## 4. 语义设计规则

### 4.1 图标家族

参考合集可以归纳为五个家族，新图标应优先复用相应语法：

| 家族 | 典型图标 | 设计语法 |
| --- | --- | --- |
| 文件与编辑 | 新建、保存、剪切、复制、删除 | 先画对象轮廓，再叠加单一动作标记 |
| 排版与布局 | 左对齐、居中、等距分布、置顶 | 使用基准线、平行线和规则块表达空间关系 |
| 画布变换 | 放大、缩小、全屏、翻转、组合 | 使用对称图形和方向标记表达变换结果 |
| 组件与数据 | 页面、文字、图片、表格、单选框 | 用最简结构表现组件的典型外观 |
| 状态与导航 | 搜索、关闭、成功、失败、展开 | 使用高辨识度通用符号，避免创造陌生隐喻 |

### 4.2 动作与对象组合

- 一个图标只表达一个主动作。
- 动作标记放在对象轮廓的右下、右上或中心，整套图标保持一致。
- 加、减、关闭等标记的尺寸应占有效绘制区的 22%–30%。
- 动作标记与对象发生重叠时，应留出清晰负形，不直接压住关键结构。
- 如果单一通用符号已经足够，例如搜索、关闭、箭头，则不额外添加容器。

### 4.3 成对与成组图标

以下图标必须成组设计和评审：

- 放大 / 缩小
- 撤销 / 重做
- 置顶 / 置底
- 水平翻转 / 垂直翻转
- 展开 / 收起
- 成功 / 失败 / 关闭
- 左 / 中 / 右对齐
- 顶 / 中 / 底对齐
- 水平 / 垂直等距分布

成组图标应共享相同外接框、轮廓粗细、箭头尺寸、留白和辅助填充比例，只改变表达差异所必需的部分。

## 5. 尺寸与落地

### 5.1 推荐尺寸

| 场景 | 图标尺寸 | 点击热区 |
| --- | ---: | ---: |
| 紧凑树节点、正文内联 | 16 px | 不单独作为按钮 |
| 菜单、状态栏 | 16–18 px | ≥ 28 px |
| 常规工具栏、输入框 | 20 px | ≥ 32 px |
| 活动轨、主操作 | 24 px | ≥ 40 px |
| 空状态或功能介绍 | 32–48 px | 按版式确定 |

- 图标尺寸与点击热区必须解耦；不得通过放大图形代替可点击区域。
- 同一工具栏只使用一个图标尺寸档位。
- 16 px 下应进行像素对齐检查；关键水平线和垂直线尽量落在整像素或半像素位置。
- 不以 CSS 非等比拉伸图标，宽高必须保持 1:1。

### 5.2 SVG 实现

优先保留参考风格的闭合填充路径：

```svg
<svg viewBox="0 0 1024 1024" aria-hidden="true">
  <path fill="var(--icon-secondary)" d="..." />
  <path fill="var(--icon-primary)" d="..." />
</svg>
```

实现要求：

- 保留 `viewBox="0 0 1024 1024"`，不在资源文件中写死像素宽高。
- 颜色通过 CSS 变量、组件属性或 `currentColor` 注入。
- 路径顺序遵循“背景层 → 辅助填充 → 主轮廓 → 反白细节”。
- 删除无意义的编辑器元数据、空分组、隐藏路径和重复节点。
- 对外部导入图标先转为轮廓并统一画布、色板和视觉线宽。
- 纯装饰图标使用 `aria-hidden="true"`；独立图标按钮必须由按钮提供可访问名称。

### 5.3 组件 Token

```css
:root {
  --icon-primary: #7d7d7d;
  --icon-secondary: #cbcbcb;
  --icon-knockout: #ffffff;
  --icon-size-inline: 16px;
  --icon-size-menu: 18px;
  --icon-size-toolbar: 20px;
  --icon-size-activity: 24px;
}

.icon {
  width: var(--icon-size-toolbar);
  height: var(--icon-size-toolbar);
  flex: none;
  overflow: visible;
}
```

## 6. 命名与资源管理

### 6.1 命名格式

文件名使用小写 kebab-case，并优先采用“对象-动作”结构：

```text
file-add.svg
folder-import.svg
align-horizontal-center.svg
distribute-vertical.svg
layer-bring-front.svg
flip-horizontal.svg
status-success.svg
```

规则：

- 不使用 `icon-` 前缀，资源目录已经表达类型。
- 不以颜色、尺寸或页面位置命名，例如禁止 `gray-left-icon.svg`。
- 成对图标使用完全一致的词序。
- 语义相同的图标只保留一个规范名称，旧名称通过代码别名兼容。

### 6.2 变体策略

- 默认只维护一个几何版本，通过组件状态切换颜色。
- 只有在 16 px 下确实无法清晰显示时，才增加 `-small` 光学校正版。
- 不为 Hover、Active、Disabled 单独导出 SVG 文件。
- 双色图标应保留主色与辅助色两个可独立映射的路径层。

## 7. 禁止事项

- 禁止混入明显不同的粗线图标或实心面状图标。
- 禁止用三种以上灰阶制造伪立体感。
- 禁止渐变、投影、高光、玻璃质感和透视效果。
- 禁止在同一图标中混用锐利直角与大半径圆角，除非语义本身需要。
- 禁止仅靠辅助填充表达核心语义。
- 禁止出现小于目标轮廓厚度的孤立细节或间隙。
- 禁止为了填满画布而无原则放大简单图形。
- 禁止直接使用文本字符代替图形路径；“T”“link”等确需文字隐喻时必须转为路径并做视觉校正。
- 禁止把工具按钮的背景、角标或状态圆点直接烘焙进基础图标。

## 8. 验收清单

新增或修改图标必须通过以下检查：

### 8.1 视觉一致性

- [ ] 使用 1024 × 1024 画布与统一安全区。
- [ ] 主轮廓视觉厚度与 48 单位标准一致。
- [ ] 只使用规定的主色、辅助色和必要反白色。
- [ ] 没有渐变、阴影、纹理或多余装饰。
- [ ] 与同组图标的大小、重心、圆角和留白一致。
- [ ] 在 16、20、24、36 px 下均可辨认且没有糊边。

### 8.2 语义与交互

- [ ] 不看文字标签也能识别对象或动作。
- [ ] 箭头、开口和层级方向明确。
- [ ] Hover、Active、Disabled 状态只由组件层控制。
- [ ] 独立图标按钮具备可访问名称与足够点击热区。
- [ ] 不仅依靠颜色区分成功、失败或选中状态。

### 8.3 工程质量

- [ ] SVG 无固定宽高、无无效分组、无编辑器私有元数据。
- [ ] 路径层级顺序正确，颜色可由 Token 覆盖。
- [ ] 文件名符合 kebab-case 与“对象-动作”命名规则。
- [ ] 未重复引入已有语义图标。
- [ ] 在浅色与深色容器中均完成对比度检查。

## 9. 设计决策优先级

当规则发生冲突时，按以下顺序取舍：

1. 语义清晰与可辨认性
2. 与同组图标的一致性
3. 小尺寸渲染质量
4. 全套图标的风格统一
5. 几何精确与装饰完整度

简化细节不会破坏语义时，应选择更简单的方案。图标首先是界面语言，其次才是独立图形作品。
